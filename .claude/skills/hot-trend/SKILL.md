# Hot Trend —— 热点选品雷达

> 定位：vend 的**上游选品环节**。本 skill 只负责「调研 → 筛选 → 锁定唯一热点 → 设计可直接落地的数字产品方案」，**不执行生产与销售**。方案落盘后停下，由用户决定是否调用 `/vend` 执行。

## 触发条件

当用户输入以下任一指令或表达类似意图时触发：

- `/hot-trend`
- "热点选品" / "趋势选品"
- "热点带货" / "蹭热点做产品"
- "现在互联网上什么最火"
- "找一个能做成数字产品的热点"
- "find a hot trend" / "what's trending now"
- 任何明确表达「想抓住当前热点做一个能卖钱的数字产品」的请求

## 核心目标与铁律

**目标**：从当前全球（英文）互联网热点中，锁定**唯一一个**最适合做成数字产品、能借势获取流量、并能真正卖出去、且实践中可落地的机会，输出一份完整可执行方案。

**铁律（不可违反）**：

1. **只输出一个热点，绝不罗列**。候选可以收集很多，但最终决策必须收敛到**唯一一个**。不要给用户「A 也不错、B 也可以」的清单。
2. **决策必须有数据支撑**。锁定的热点必须能拿出趋势/热度/付费意愿的真实证据，不能凭感觉。拿不出证据的，换一个。
3. **必须可落地**。方案要能回答：用什么形态、几天能产出、在哪上架、流量从哪来、定价锚在哪、版权合规有无硬伤。任何一环答不上来，这个热点就不算合格，继续找。
4. **时效窗口要够**。只蹭「几小时就过气」的梗毫无意义，必须保证有足够长（≥2 周）的销售窗口。
5. **必须与已有数字商品差异化**。启动时先盘点 `docs/product/` 下已有的选品方案与成品（`hot-trend-*.md` 及各类数字产品），列出已覆盖的领域 / 品类清单；本次锁定的热点**领域必须与这些不同**，候选阶段就主动排除已覆盖领域，避免反复造同类产品。
6. **必须给出引流 + 销售方案**。光有热点和产品不够，方案必须同时包含**引流打法**（目标关键词、主攻平台、引流钩子、首发内容）与**销售打法**（上架渠道、定价与优惠券、收款与提现路径）。渠道选择遵守 `.claude/rules/available-channels.md`：Payloadz + PayPal 主链路，小红书国内，**Gumroad / TikTok 不可用**。

## 目标市场

**全球市场为主，英文语境**。

- 数据源：英文平台热点榜（详见下节）
- 变现渠道：Gumroad、Payhip、Payloadz、Lemonsqueezy 等国际数字产品平台
- 产品语言：英文（产品文案、关键词、上架信息均用英文）
- 收款：与 vend 配置一致（可提现到 HK / CN 银行）

## 数据源（全球英文热点榜）

分三类并行采集，避免单一来源偏差：

**① 趋势与搜索类（看热度斜率）**
- Google Trends — Daily / Real-time search trends、trending searches
- Exploding Topics / Glimpse — 专门捕捉「正在爆发」的上升中趋势
- Pinterest Trends — 适合素材 / 设计 / 生活方式类
- YouTube Trending + 搜索 autofill

**② 社交讨论类（看话题热度与情绪）**
- X / Twitter — Trending topics、相关 hashtag
- Reddit — r/popular、各垂直 sub 的 rising / hot
- TikTok — Creative Center trending、Discover hashtag

**③ 产品与技术类（看付费意愿与品类）**
- Product Hunt — 今日 / 本周榜，反映「人们愿意为这类工具付费」
- Hacker News — front page，开发者 / 技术人群付费意愿强
- Etsy / Gumroad 搜索 autofill — 直接看「现在有人在搜什么数字产品买」

> 跨平台共振是强信号：同一个话题在 ≥3 个不同类来源同时上升，优先级大幅提高。

## 搜索工具调用

优先使用已安装的 **anysearch** skill（推荐搜索工具）并行批量抓取：

```bash
# 从 runtime.conf 读 <cmd>，例如 python3 <skill_dir>/scripts/anysearch_cli.py
# 阶段1：并行采集多源热点（batch_search 一次发多个 query）
<cmd> batch_search --queries '[
  {"query":"Google Trends daily trending searches today"},
  {"query":"Exploding Topics trending this month"},
  {"query":"Reddit r/popular rising topics this week"},
  {"query":"Product Hunt top products today this week"},
  {"query":"TikTok trending hashtags this week"},
  {"query":"X Twitter trending topics right now"},
  {"query":"Hacker News front page discussion"},
  {"query":"Gumroad top selling digital products this week"}
]'

# 对重点候选做垂直/社交域深挖
<cmd> get_sub_domains --domain social_media
<cmd> search "<候选话题> discussion on X and Reddit" --domain social_media --sub_domain <returned> --max_results 5

# 抓取某条榜单页全文验证
<cmd> extract "https://trends.google.com/trending?geo=US"
```

**降级策略**：anysearch 不可用（无 Key / 配额耗尽 / 服务报错）时，告知用户并改用内置 `WebSearch` + `WebFetch` 完成同样的多源采集。**绝不能因为某一个搜索工具挂了就放弃**——换工具继续。

## 五阶段工作流

> **前置 · 已有资产盘点**（阶段 1 之前必做）：扫描 `docs/product/` 下所有 `hot-trend-*.md` 选品方案与已产出的数字产品，整理出「**已覆盖领域 / 品类清单**」，作为后续候选的排除集。本次选品领域必须在该清单之外（对应铁律 5）。若 `docs/product/` 为空或不存在，跳过本步。

### 阶段 1 · 多源并行采集（广撒网）

- 用 `batch_search` 一次抓 8 个以上数据源的热点榜，各取 top 5-10。
- 汇总成 **15-30 个原始候选**，去重，记录每个候选首次出现的来源平台。
- 此阶段**不做判断**，只做收集。

### 阶段 2 · 评分卡快速过滤（粗筛）

对每个候选用**五维评分卡**打分（每维 0-10）。淘汰硬伤项，保留 **3-5 个强候选**进入下一阶段。

### 阶段 3 · 深度核查与收敛（锁定唯一）

对 3-5 个强候选逐一深挖，收敛到**唯一一个**：

- 拉取趋势曲线，确认「正处于上升期」而非见顶。
- 查同类已售数字产品（Gumroad / Etsy 搜索），确认有**付费证据**与**定价锚**。
- 查目标关键词搜索量与竞争度，确认有**可蹭的流量入口**。
- 过一遍**可行性核查清单**，任一项不过即降级。

> 收敛时如果出现两个候选势均力敌，**默认选时效窗口更长、生产成本更低、版权风险更小的那个**。决不并列输出。

### 阶段 4 · 产品化设计

把唯一热点设计成一个完整数字产品：形态 → 内容大纲 → 成品样例 → 定价 → 标题与文案 → 流量打法 → 落地步骤。

### 阶段 5 · 输出可落地方案

把方案写入文件（见「输出文件」），向用户**简报唯一热点 + 一句话理由 + 数据依据**，然后**停下**，提示「确认后可调用 `/vend` 执行生产与销售」。不要自动进入 vend。

## 五维评分卡（核心筛选逻辑）

每个维度 0-10 分，总分 = 加权和。**任何一维低于门槛直接淘汰，不进总分排名。**

| 维度 | 权重 | 满分标准（10 分） | 门槛 |
|------|------|------------------|------|
| **① 热度上升斜率** Trend Velocity | ×2.0 | 趋势曲线陡峭上升，跨 ≥3 个平台共振 | ≥5 |
| **② 数字产品适配度** Product Fit | ×1.5 | 天然能做成模板 / 提示词包 / 指南 / 工具 / 素材库 | ≥6 |
| **③ 流量潜力** Traffic Potential | ×1.5 | 有高搜索量主词 + 长尾词，平台算法友好，有明确可蹭 hashtag | ≥5 |
| **④ 付费意愿** Willingness to Pay | ×2.0 | 对应强痛点（赚钱 / 省时 / 求职 / 学技能），有同类付费产品佐证 | ≥6 |
| **⑤ 可行性与时效** Feasibility & Window | ×2.0 | ≤3 天可产出高质量成品；无版权 / 合规硬伤；窗口 ≥2 周；渠道无门槛上架 | ≥7 |

> 加权最大的三块是「付费意愿」「可行性与时效」「热度斜率」——这正是「能卖得动、做得出来、踩得准」三件事。纯新闻事件、纯娱乐梗通常在②④上得分很低，自然被淘汰。

## 硬性淘汰门槛（一票否决）

命中任一项，该候选**立即出局**，不参与评分：

- ❌ 时效窗口 < 2 周（几小时 / 一两天的过气梗）
- ❌ 有明确版权 / 商标 / 合规硬伤（影视 IP、品牌 logo、受版权保护内容）
- ❌ 无法数字化（实体商品、需要线下交付、需要持续人力服务）
- ❌ 无任何付费证据（没人愿意为这类需求花过钱）
- ❌ 涉政 / 灾害 / 悲剧 / 严重社会争议（品牌与合规风险）
- ❌ 变现渠道不可达（目标平台不支持该品类 / 有上架门槛过高）

## 数字产品形态库（按生产速度与适配度排序）

锁定热点后，从以下形态里选**适配度最高 + 生产最快**的一种（可组合）：

1. **Prompt 包 / AI 提示词模板集** —— 适配 AI 类热点，生产极快（1 天）
2. **Notion / Figma / Excel 模板与系统** —— 适配效率 / 设计 / 管理类热点（1-2 天）
3. **电子书 / 实战指南 / Playbook / Checklist 包** —— 适配「方法论」类热点（2-3 天）
4. **素材库 / 资源包 / 数据库**（图标、字体、音效、Prompt 图、数据导出）—— 适配创作类热点（2-3 天）
5. **短课程 / 视频教程 / Workshop** —— 适配技能学习类热点（3 天+，生产成本较高，慎选）
6. **小工具 / 脚本 / SaaS MVP** —— 适配技术 / 开发者热点，溢价高但生产风险大（除非有现成脚手架）

## 可行性核查清单（最终锁定前必过）

- [ ] 生产周期 ≤ 3 天，且单次产出即为可售成品
- [ ] 无版权 / 商标 / 合规硬伤
- [ ] 时效窗口 ≥ 2 周
- [ ] 变现渠道可达（Gumroad / Payhip 无门槛上架）
- [ ] 有明确目标人群，且至少 1 个免费流量入口（X / Reddit / TikTok / PH / HN）
- [ ] 定价有同类产品锚定（非完全无参照）
- [ ] 我能用现有工具 / 能力独立完成，无需大额资金投入

## 重试与容错

- **幂等重试**：搜索 / 抓取类操作默认重试 3 次，指数退避（1s/2s/4s）。
- **单源容错**：任一数据源连续失败，跳过并用其余源补充，**保证至少 5 个有效来源**参与决策。少于 5 个来源则向用户说明数据覆盖有限。
- **不无限循环**：同一搜索重试 3-5 次仍失败，换工具（anysearch ↔ WebSearch）或换源，不死磕。
- **保存中间状态**：阶段 1-2 的候选清单先落盘到 `docs/history/hot-trend-candidates-<date>.md`，便于中断恢复与事后复盘。

## 安全与边界

- **不蹭危险流量**：拒绝涉政、灾害、悲剧、严重社会争议类热点。
- **不做侵权内容**：不搬运受版权 / 商标保护的素材、IP、品牌资产。
- **不夸大承诺**：预估指标必须给区间并标注不确定性，不写「保证月入 X 万」。
- **数据真实**：所有热度 / 趋势 / 付费证据必须来自实际抓取，**严禁编造数字或来源**。拿不到真实证据的热点，降级或舍弃。
- **隐私**：执行中获取的平台账号、API Key 等敏感信息只存本地配置，不写回本 SKILL 或方案文件。
